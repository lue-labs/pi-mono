# Fork Changelog

Fork-specific changes maintained by valkyriweb. Upstream package changelogs stay reserved for upstream release notes and upstreamable changes.

Release numbers track the fork's published `@valkyriweb/*` packages (GitHub Packages, versioned in lockstep via Changesets); dates are release-tag creation dates. Entries were back-attributed to releases via git blame → earliest containing release tag.

## [Unreleased]

### Changed

- **Forked named Agent profiles retain role guidance without hidden tool blocking.** `context: "fork"` remains a permissive self-fork with the caller's cache-compatible system/tool prefix; the selected named prompt moves to the trailing task message, and run details warn when ordinary profile tool filtering is bypassed. Existing profile/depth caps on nested Agent access remain enforced. This matches Claude Code's “fork yourself” semantics while keeping Pi's named-profile-plus-fork compatibility.

- **Agent tasks now use an outcome-first calling-agent contract instead of child/subagent identity framing.** The universal trailing task message says the Agent tool call and later course corrections direct the work, returns the completed result to the calling agent, and accurately states depth-capped Agent availability. Built-in profile prompts and model-facing Agent tool guidance are substantially shorter: they retain capabilities, constraints, expected evidence, and verification while removing duplicated tool tutorials and procedural search choreography. `Agent`/`Task` call shapes and `subagent_type` remain compatible. Static prompt/tool-description bytes rewarm once on rollout and remain deterministic; fork mode still preserves the calling session's system/tool prefix byte-for-byte.

### Fixed

- **Failed background Agent runs can be safely dismissed from the Agents pane.** A remappable `d` action acknowledges only terminal failed runs, moving their aggregate and child snapshots from Needs input to Completed while retaining their status record, session references, and output references for inspection. Cancelling an interrupted run also normalizes its interrupted children to cancelled so flattened panels do not retain stale attention rows. This fixes parallel launches that fail before any child starts (such as an unavailable model), plus recorded child failures and interrupted-then-cancelled children that otherwise remain permanently attention-blocking.

- **Opaque Codex gateways can opt out of ChatGPT-only transport features.** `OpenAICodexResponsesCompat` now supports model-level `supportsWebSocketTransport:false` and `supportsZstdRequestCompression:false` alongside `sendChatgptAccountId:false`. Gateway models can force SSE, send an uncompressed JSON body, and omit the ChatGPT account header while preserving the native Codex deferred-tool wire contract; direct ChatGPT Codex defaults are unchanged.

- **Provider requests and compaction no longer retain unbounded image payloads.** The SDK and session cache heartbeat now keep only the newest supported images within a 3 MiB aggregate base64 budget on their transient request contexts, replacing older images with a short placeholder while preserving durable session history. A single oversized tool-result image is saved under `.pi/tool-artifacts/` and represented by an artifact pointer when persistence succeeds; a write failure preserves the image in durable history while the transient budget still omits it. All core compaction requests are media-free. No system prompt or tool schema bytes change.

## [0.82.0] - 2026-07-11

### Added

- **Model-gated GPT-5.6 Ultra thinking mode.** Pi now represents `ultra` as an opt-in thinking level for Sol and Terra: maximum reasoning plus a client-side orchestration signal exposed through CLI/settings/selectors/agent configuration. Orchestration extensions can use that signal for proactive delegation. OpenAI Responses and ChatGPT Codex Responses normalize Ultra to native wire-level `reasoning.effort: "max"`; literal `"ultra"` is never sent to either endpoint. Unsupported models clamp to their highest declared thinking level.

- **Compact semantic agents footer and parked-session metadata (`#agent-run-label-parked-idle`).** Unified task snapshots now expose optional caller labels, persisted session paths, and needs-input state; persistent background forks mark intentional parks explicitly and render only that `interrupted` lifecycle as UI-only `idle` across footer, pane, status, and race-safe per-turn model-visible lifecycle-notification surfaces, and are excluded from bounded terminal-history eviction while still alive. The footer reports only `working`/`needs input` counts plus the agents navigation hint, invalidates memoized extension-footer lines on lifecycle changes, while its pane groups Needs input, Working, and Completed rows and can open a parked run's persisted session through the existing zoom pane. Display/control metadata plus appended lifecycle-notification wording only; no system prompt, tool schema, model request, or cache-key change.

### Fixed

- **Dynamic registered footer pills now repaint when task/extension state changes.** Whole-footer memoization excluded registered pill output from its change-guard and `FooterComponent.invalidate()` was a no-op, so any `registerFooter` consumer (agents, monitor, workflow pills) could stay hidden, stale, or visible after completion until an unrelated footer input changed. Pill `visible()`/`render()` output now participates in the render memo key — extensions repaint on the next render pass with no invalidation wiring — and `invalidate()` actually evicts memoized lines for core agent-run/background-bash subscriptions. Git branch caching remains provider-owned. Regression coverage proves both paths (explicit invalidation and no-invalidation extension updates) and fails on the prior implementation.

- **Session-liveness startup sweep no longer freezes terminal input on large session trees.** The deferred startup sweep for `.live` markers orphaned by crashed processes (shipped 0.78.3) walked the entire sessions tree synchronously, freezing terminal input for several seconds on a 37k-entry tree; it now yields immediately and traverses asynchronously with directory entries while preserving the same best-effort dead/stale cleanup. Regression: `test/session-liveness.test.ts` (nested async sweep + missing-directory cases). ([#267](https://github.com/valkyriweb/pi-mono/pull/267))

## [0.81.0] - 2026-07-10

### Changed

- **Fork-delta static analysis tightened: delta = fork-ADDED files vs `upstream/main` tip, and error-severity dependency-cruiser violations now block.** `scripts/check-fork-delta-static.mjs` previously diffed against the merge-base, which counted upstream-added files arriving via sync merges as "fork delta" (234 files, 406 depcruise warns); the delta is now `git diff --name-only --diff-filter=A upstream/main HEAD` (78 truly fork-added files, 69 warns), `resolveMergeBase()` removed and the upstream fetch shallowed to `--depth=1`. Ratchet: error-severity depcruise boundary violations exit 1 without `--strict` (0 findings at introduction — gate armed green); warn-severity cycles and all knip findings stay advisory. CI step's `continue-on-error` removed accordingly.

- **Migrated the fork's typecheck/build toolchain to stable TypeScript 7 (`typescript@7.0.2`, native `tsc`) off the `@typescript/native-preview` (`tsgo`) binary (`#ts7-native-tsc-stable`).** Typechecks/builds now run on the shipped stable compiler instead of a Jan-2026 preview. Pins `typescript 5.9.3 → 7.0.2` exact (root + `packages/agent` + `packages/coding-agent`; `ai`/`orchestrator`/`tui` inherit via the workspace), drops `@typescript/native-preview`, and swaps every `tsgo → tsc` call-site (root `check`, `orchestrator` dev+build, `ai`/`agent`/`tui`/`coding-agent` build). Stable TS 7 ships **no programmatic compiler API until 7.1**, and `scripts/check-ts-relative-imports.mjs` (the repo's only compiler-API consumer) is reimplemented on **`oxc-parser@0.139.0`** (the Rust TS parser used by oxlint, added as a root devDep) — adding a TS6 API alias (`@typescript/typescript6`) instead would pull a transitive `tsc` bin that shadows native `tsc@7` under npm's flat `.bin`, so the alias is dropped entirely. The rewritten checker detects all four relative-`.js` violation shapes (static import / re-export / dynamic `import()` / `import(...)` type) with correct `line:col`. `tsconfig.base.json` `target`/`lib` moves `ES2022 → ES2024`: stable `tsc` correctly enforces the ES2024 RegExp `v`/`unicodeSets` flag (`\p{RGI_Emoji}` in `packages/tui/src/utils.ts`, `TS1501`) that `tsgo` let slide, and the `>=24.14` Node engine floor is ES2024-safe. No runtime/library behaviour change; emit differences are limited to reduced down-levelling for the Node 24 runtime. Full `npm run check` and `npm run build`+`test:build-gate` green (all 5 packages compile on native `tsc@7`; system-prompt 35, cache-stability 48, loader-resolver 38, e2e 256/256). Fork-local build-toolchain patch (re-conflicts on upstream sync until upstream adopts stable TS7 / TS 7.1 restores the compiler API); logged in `my-pi/docs/pi-fork-patch-inventory.md`, revisit trigger `my-pi/plans/042-ts7-1-revisit.md`. ([#251](https://github.com/valkyriweb/pi-mono/pull/251))

- **`test:my-pi-extensions` now skips absent or dirty sibling `my-pi` checkouts instead of failing shared-session fork gates.** The script delegates to `scripts/run-my-pi-extension-gate.mjs`, preserves full extension-gate coverage when the sibling checkout is clean, warns and skips when the default `../my-pi` tree contains other-session WIP, and supports `MY_PI_EXTENSION_GATE_DIR` for pointing CI/local verification at a clean my-pi worktree.

- **Advisory static analysis (knip + dependency-cruiser) is now scoped to the fork's delta against `upstream/main`, not the full tree.** This fork is a long-lived fork of `earendil-works/pi-mono` where nearly all source is upstream-owned, so running knip/depcruise unscoped mostly surfaces findings the fork can't act on. Added `scripts/check-fork-delta-static.mjs`: resolves/fetches the `upstream` remote, computes `git diff --name-only $(git merge-base HEAD upstream/main)` against `packages/*/src/**/*.ts`, runs both tools in full and filters their JSON output down to files/violations inside that delta set. `package.json` now exposes `lint:fork-delta` (the CI-facing advisory entry) plus `lint:knip:all`/`lint:arch:all` as explicit full-repo opt-ins; CI's two advisory steps collapsed into one `npm run lint:fork-delta` step. The script is fully advisory (exit 0) unless invoked with `--strict`, and skips cleanly (exit 0) if upstream can't be fetched (offline/network-restricted).

### Fixed

- **`version-packages` now regenerates `packages/coding-agent/install-lock` after `changeset version`.** The changesets Release workflow regenerates `package-lock.json` and the coding-agent shrinkwrap on the `changeset-release/main` branch but left `install-lock` pinned to the pre-bump version, so every regenerated release PR failed CI's `check:install-lock:coding-agent` (`install-lock is out of date`) and needed a manual `npm run install-lock:coding-agent`. Appending the generator to the `version-packages` script heals the release branch automatically on the next Release run.

- **The trailing tool call of a `length`-stopped assistant message is no longer executed with truncated arguments.** When a response is cut at the output-token limit mid tool call (2026-07-09 fable incident: a near-full 200k window clamped `max_tokens` to ~11k and a monolithic `write` truncated mid-arguments), lenient partial-JSON parsing (`parseStreamingJson`, `packages/ai/src/api/anthropic-messages.ts`) yields incomplete arguments. The agent loop (`packages/agent/src/agent-loop.ts`) executed the call anyway, producing either a misleading schema-validation error (`Validation failed for tool "write": content: must have required properties` — no hint the call was cut off, so the model retried the identical oversized call) or, in the worst case, a silently truncated payload that still validated (a `write` whose `content` string was cut mid-way would have written a corrupt file with no error at all). `prepareToolCall` now short-circuits the trailing tool call of a `length`-stopped message with an explicit error tool result telling the model the call was cut off by the output-token limit and to emit smaller chunks (`write` a skeleton + extend with `edit`) instead of retrying verbatim. Earlier complete tool calls in the same message, `length` stops whose final block is text, and all other stop reasons are unchanged. Incident analysis: `my-pi/docs/incidents/2026-07-09-fable-length-truncation-loop.md`; companion fix for the post-compaction `max_tokens: 1` dead turn landed in [#240](https://github.com/valkyriweb/pi-mono/pull/240). Regression coverage in `packages/agent/test/agent-loop.test.ts` ("length-truncated trailing tool call guard": 2 bug cases fail on baseline, pass with the fix; 3 regression guards).

- **First turn after a compaction no longer truncates to zero output (notably `claude-fable-5` with adaptive thinking).** After compaction, `estimateContextTokens` (`packages/ai/src/utils/estimate.ts`) anchored on the retained assistant message's stale pre-compaction `usage.totalTokens` (~194k while the real compacted context was ~55k), so `clampMaxTokensToContext` collapsed `max_tokens` to ~1131; the Anthropic `forceAdaptiveThinking` branch then let unconstrained adaptive thinking consume the whole budget, ending the turn with `stopReason:"length"` and no visible output (recovered only by `retry.maxRetries`). Two guards: (1) `estimateContextTokens` discards a usage anchor that exceeds a fresh recount of current messages + system/tools prefix by more than `STALE_USAGE_RECOUNT_FACTOR` (2×) and falls back to the recount; (2) the `forceAdaptiveThinking` path disables thinking when the clamped `max_tokens` is below `MIN_THINKING_BUDGET * 2`, mirroring the existing budget-branch floor guard (`#thinking-budget-floor`) so the budget yields visible output instead of pure thinking. Both touch per-request `max_tokens`/`thinking` only — no `params.system`/`tools[]` byte change (cache-safe). Reference note (binlens on the shipped CC/Codex binaries): neither derives per-request `max_tokens` from `window − estimate` — Claude Code recovers reactively off the provider's `input length and max_tokens exceed context limit` error, Codex auto-compacts proactively below the window; the estimate-based clamp is Pi's architectural outlier, so CC-style reactive recovery is noted as an upstream follow-up. Regression coverage: `packages/ai/test/estimate-stale-usage-anchor.test.ts`, `packages/ai/test/anthropic-adaptive-thinking-budget-floor.test.ts` (4 bug cases fail on baseline, pass with the fix). ([#240](https://github.com/valkyriweb/pi-mono/pull/240))

### Fixed

- **Interactive footer now shows the active provider adapter lane for Claude Code and Codex sessions.** `packages/coding-agent/src/modes/interactive/components/footer.ts` now derives a compact `adapter:<lane>` segment from concrete request/session metadata already present in core (`state.model.api` / provider, latest assistant metadata, and OAuth-backed Anthropic lanes) instead of guessing from the footer label alone, so the live TUI clearly distinguishes `adapter:claude-code` from `adapter:codex`. The beta is now appended only when the effective request actually uses `ttl: "1h"`, so short/none retention and compat-disabled long retention stay unchanged. Regression coverage in `packages/ai/test/anthropic-cache-ttl-header.test.ts` asserts the request sends both the payload TTL and beta header for the default long-retention path, and omits the beta for short/none or unsupported-long cases.

Also capped non-git `.agents/skills` ancestor discovery at the repo/workspace/home boundary instead of walking to `/`, avoiding stray ancestor scans outside the active workspace. Regression coverage: `packages/coding-agent/test/skills.test.ts`, `packages/coding-agent/test/package-manager.test.ts`.

- **Foreground Agent runs now auto-background on child provider retry/rate-limit backoff when the parent has a completion-notification sink.** A foreground `Agent`/`Task` call that enters `auto_retry_start` no longer blocks the parent for the whole exponential backoff window: the executor marks the existing recent run as `background`, returns a running `runId` with the retry/error snippet, keeps the child session alive under the existing controller, and later emits the normal `agent_completion` wake when the backgrounded run terminates. The parent can immediately `interrupt`, `cancel`, `resume` (single runs), or `inject` via the existing Agent control actions. Headless/no-notification runtimes keep the safer foreground wait so no in-process child is stranded without a parent wake. Lifecycle/status only; no `tools[]`, system prompt, model request, or cache-key surface; terminal wake uses the existing dynamic `agent_completion` message. Regression: `test/suite/agent-tool-single.test.ts` (auto-background + cancellable run).

## [0.80.8] - 2026-07-08

### Added

- **`ToolDefinition.resumePendingCall` opt-in seam for interactive tools to survive `pi --resume` (`#resume-pending-interactive-tool-call`).** Sessions killed while a UI-only tool (e.g. my-pi's `AskUserQuestion`) was awaiting an answer previously lost the pending question silently on resume: the generic orphaned-tool-call fallback (`packages/ai/src/api/transform-messages.ts`) fills any unresolved `tool_use` with a synthetic "No result provided" error the next time a message interrupts the transcript, and the model proceeded as if the user had answered nothing (live-verified: a killed/resumed AskUserQuestion session replied "No color selected. What would you like me to do?" instead of re-showing the dialog). Added an explicit, default-off `resumePendingCall?: boolean` field to `ToolDefinition` and a new `AgentSession.resumePendingInteractiveToolCall()` method: when a loaded/resumed transcript ends on exactly one unresolved `toolCall` for a tool that opted in, the tool is re-executed (its persisted arguments are the only pending state - nothing lives in extension-local memory or the cached system prefix) and the result is delivered through the normal `agent.prompt()` pipeline. Wired into both resume paths (`finishSessionReplacement` for `/resume`, `/new`, `/fork`, and the top-level `createAgentSessionRuntime()` for cold-boot `pi --resume`). Non-opted-in tools (bash, edit, etc.) are completely unaffected - the existing orphaned-call fallback still applies to them. Regression coverage in `packages/coding-agent/test/suite/regressions/resume-pending-interactive-tool-call.test.ts` (opted-in tool replays and the agent continues; non-opted-in tool is left alone; ambiguous transcripts - trailing user message, or two pending calls in one turn - no-op).

### Changed

- **Cut upstream-sync conflict surface (`.gitattributes` + tracked-tree cleanup).** Added `/package-lock.json merge=ours` so the root npm lockfile (regenerated from `package.json` on install, never byte-matching upstream) stops hard-conflicting on every sync — same pattern + rationale as the generated model registries (ADR `docs/adr/0002`); the `ours` driver is already registered by `scripts/setup-merge-drivers.sh`, scoped to the root lockfile only so example-extension lockfiles stay upstream-owned. Removed 124 fork-only working-cruft files from the tracked tree (`handoff/` planning notes, `next-steps.md`, `pi-agent-tool/` autoresearch captures / jsonl logs / scratch scripts), none referenced by any tracked build/test/workflow/script and all recoverable from history. No core code / `tools[]` / system-prompt / cache surface touched; operationalizes ADR 0004 (fork hygiene) by shrinking divergence + audit surface ahead of the `pi-agents` extraction. ([#104](https://github.com/valkyriweb/pi-mono/pull/104))

### Fixed

- **Successful child-agent `auto` routing notes no longer include fallback re-dispatch advice (`#model-resolve-hook`).** `createAgentSession()` now distinguishes a successful auto-routing note from a true routing failure (`modelRoutingFailed`), so `runChild` still surfaces semantic-router selection metadata to the delegating model but only appends "re-run the task with an explicit model override" when the router was unavailable or returned no decision. Regression: `test/agent-child-auto-routing.test.ts` asserts successful route notes omit the fallback advice while failure warnings keep it.

- **Release CI startup validation now grants the reusable binary build workflow its required package-read permission.** `.github/workflows/release.yml`'s `binaries` caller job already granted `actions: read` for `stage-github-release`, but `build-binaries.yml`'s `build` job also requests `packages: read` to install private `@valkyriweb/*` packages. Because job-level permissions replace workflow-level permissions, the called workflow asked for a permission the caller job lacked and GitHub rejected every Release run at startup.

- **Child-agent `auto` alias now falls back to the family medium tier instead of the parent model (`#model-resolve-hook`).** When `settings.subagents` (or agent frontmatter/task) selects an auto alias, `resolveAgentModel` previously returned the parent model as the concrete pre-routing model — so a semantic-router outage silently ran every non-fork child on a frontier parent (e.g. fable). The auto branch now resolves through the shared family-aware tier logic (`resolveTierAliasModel`, extracted from the tier-alias branch) at `medium`, falling back to the parent only when the provider has no medium candidate. Per-prompt routing via the `model:resolve` filter (requestedModel + routingMetadata in `runChild`) is unchanged; fork-mode children still drop subagent defaults and inherit the parent for cache identity. Regressions in `test/agent-model-selection.test.ts` (auto → family medium, fail-on-baseline; no-candidate → parent). Additionally, **router failures are now surfaced to the delegating model**: `runChild` lifts the session-creation `modelFallbackMessage` (router unavailable / no routing decision on an auto alias) into the parent-facing run `warnings` with explicit re-dispatch advice ("re-run the task with an explicit model override"), and the prompt-boundary resolver (`_resolvePendingAutoModelForPrompt`) emits the `model-routing-warning` custom message for router-unavailable too, not just no-decision. Regression: `test/agent-child-auto-routing.test.ts` ("surfaces router-unavailable as a parent-facing run warning").

- **Cache-health footer warning now reports unhealthy cache writes, not any large write.** Replaced the misleading `prefix_cold_write` warning with `cache_write_unhealthy`, gated by both meaningful write size and poor cache warmth, so warm turns with expected top-up writes no longer render as cache busts. The interactive footer label now renders `🔥write` instead of `🔥prefix`. Regression coverage in `packages/coding-agent/test/cache-health.test.ts` locks the healthy warm-write and unhealthy cold-write cases.

- **Footer pill selection now repaints correctly after keyboard navigation, and child-agent tier aliases prefer the active model family.** `FooterComponent` includes the selected extension-footer id in its render cache key and invalidates cached footer lines when selection changes, so Down/Up over bg/shell/agents pills visibly moves the highlighted block instead of reusing stale dim text. `clawrouter` child-agent tier resolution now prefers same-family aliases (`gpt-*` for GPT-selected parents, `claude-*` for Claude-selected parents) before falling back across families. Regressions cover footer render-cache invalidation and same-family alias selection.

- **Child Agent runs now show provider retry/rate-limit backoff in the Agent tool instead of looking idle.** Child sessions already emitted `auto_retry_start`/`auto_retry_end`, but `core/agents/executor.ts` ignored those events, so a clawrouter/Claude rate-limit looked like a stuck `running · 0 tool uses` row until the retry either recovered or failed. The executor now maps retry events into `AgentRunDetails.recentOutputSnippets` and live task messages, so the existing Agent renderer shows `Rate limited/overloaded; auto-retry …` directly in the tool panel. Display/status only; no `tools[]`, system prompt, model request, transcript, or cache-key surface. Regression: `test/suite/agent-tool-single.test.ts`.

- **Extension main panes (e.g. the footer agents-status pill's pane) never received keyboard focus once opened, so no keystroke ever reached their `handleInput` -- this is the actual root cause of "Enter doesn't work" on the agents footer pill.** `interactive-mode.ts`'s `showExtensionMainPane` mounted the pane component into `chatContainer` but, unlike every other editor-replacing surface in the file, never called `ui.setFocus(component)` -- all keystrokes kept routing to the (empty, focused) main editor; only Escape worked via the separate `onEscape` passthrough. This made the zoom-routing fix directly below (and the pane's pre-existing up/down navigate + `x` stop) unreachable dead code in the live product even though it was unit-tested correctly -- the unit tests construct the pane directly and call `handleInput` themselves, bypassing the missing focus wiring, which is why live tmux verification (not the test suite) caught it. Fixed by adding the missing `ui.setFocus(component)` on show and `ui.setFocus(this.editor)` on hide. Regression: `test/interactive-mode-footer-nav.test.ts` ("focuses the pane component when it is shown...", "restores focus to the editor when the pane is hidden", fail on baseline).

- **Agents footer pill: Enter on a running background agent row now attaches to its live transcript instead of only ever showing a static status-text detail.** `core/extensions/agents.ts`'s footer-activated `AgentsPane` (added in #196) reused `agent-runs-selector.ts`'s row/detail formatters but never wired the row-scoped zoom entry (`shouldZoomAgentRunRow` + the `pi-agent-ui` "zoom" main pane) that `/agents runs` already gets from `handleAgentRunSelectorAction` -- Enter on this pane always fell to the static detail view regardless of task state, so selecting the pill and pressing Enter to "enter into the agent session" produced a text dump instead of an attach, reported as "it doesn't work". Added a generic, additive `pi.hasMainPane(id)` / `pi.cwd` extension-API seam (existence check for a registered main pane + the extension's working directory, mirroring the existing `showMainPane`/`hideMainPane`) so core can safely probe whether a richer pane is available before routing into it, falling back to the pre-existing static detail when it is not. Regression: `test/agents-ui.test.ts` ("Enter zooms into the live transcript...", "Enter falls back to static detail...", fails on baseline).

- **Agents footer pill: distinct colors for "needs attention" vs "still running", and the pending question text now shows inline on the row.** The pill previously rendered every state identically (plain text, or accent-only when the pill itself had nav focus) -- a background agent silently blocked awaiting input read no differently than one still working. `render()` now colors the pill `warning` when any relevant task is interrupted, failed, or a running local_agent has `needsAttention`, and `dim` otherwise; `agent-runs-selector.ts`'s `formatAgentRunRow` now inlines the actual pending question (`run.attentionMessage`) instead of only the "needs attention" label. Regression: `test/agents-ui.test.ts` ("footer pill uses a distinct color..."), `test/agent-runs-selector.test.ts` ("row inlines the pending question text...").

- **Footer agent-status pill lost its Up/Down selection highlight (and queued-message recall) in any session where an extension replaced the editor.** `setCustomEditorComponent` — invoked by `ctx.ui.setEditorComponent()` (used by `pi-syntax-input` and other editor-wrapping extensions) — forwarded `onEscape`/`onCtrlD`/`onPasteImage`/`onExtensionShortcut`/`actionHandlers` from `defaultEditor` onto the replacement editor but never forwarded `onPreInput`, the seam `setupKeyHandlers()` wires footer pill Up/Down cycling and queued-message recall through. Enter still worked (it runs through the separately-forwarded `onSubmit`), which masked the break in prior fix rounds even after the render-side selected-highlight fix (#200) landed — the render code was correct, but `onPreInput` never reached the live editor to update `selectedExtensionFooterId` in the first place. Added the missing forward alongside the existing ones. Regression: `packages/coding-agent/test/interactive-mode-footer-nav.test.ts` ("forwards onPreInput to a replacement editor installed via setEditorComponent", fails on baseline).

- **Provider-qualified model references no longer resolve through proxy provider model IDs.** `provider/model` refs now match only that provider and never fall through to bare-ID or fuzzy matching, so an unavailable `openai/...` / `openai-codex/...` ref cannot silently select a Kilo/OpenRouter proxy model such as `kilo/openai/...`. Regression coverage in `packages/coding-agent/test/agent-model-selection.test.ts` pins the failure mode.

## [0.80.7] - 2026-07-03

### Added

- **`ForkAgentOptions.detachFromParent` opt-out of the parent session abort signal (`#fork-detach-from-parent`).** `engine.ts` fork() chains `AbortSignal.any([opts.signal, parentSnapshot.signal])`, so `AgentSession.dispose()`/`agent.abort()` on a session replace/reload cancels an in-flight fork. The new additive, default-off `detachFromParent` flag skips the parent snapshot signal (`if (snapshot.signal && !opts.detachFromParent) signals.push(snapshot.signal)`), so a best-effort background fork runs on the caller's own signal and is bounded by the caller's drain instead — pi-memory's turn-end extraction flushed on `session_shutdown`. Default (unset/false) preserves prior behaviour; lifecycle flag only, not part of the cached prefix. Also locks the drain-before-abort invariant (`teardownCurrent` awaits `emitSessionShutdownEvent(session_shutdown)` before `session.dispose()`) with a regression test in `packages/coding-agent/test/agent-session-runtime-events.test.ts` ("awaits an async session_shutdown handler (drain) before disposing the old session"). - **Auto-background-on-timeout for the built-in `bash` tool** (mirrors Claude Code's `tengu_bash_command_timeout_backgrounded`). Instead of killing a timed-out foreground command, the exec layer now **detaches the still-running process** and adopts it into the background-job registry (`adoptBashBackground` in `core/tools/bash.ts`): a race between real exit and the timeout resolves to `{ exitCode: null, backgroundedJobId }`, the foreground `onData` listeners are detached, future stdout/stderr is redirected to `~/.pi/agent/bash-bg/<bgId>.log`, and the adopted child's pid stays tracked (the bg job owns it). ### Changed

- **Bash foreground-timeout moved behind an additive `onBashTimeout` seam; core default is now upstream-neutral (kill).** The exec loop no longer hardcodes a detach policy; on timeout it consults a pluggable resolver given a `BashTimeout` context (`command`, `cwd`, `timeoutMs`, `background()`, `kill()`) and acts on the `BashTimeoutOutcome` (`{ backgroundedJobId }` or `{ failed }`). The **core default kills and reports `Command timed out after Ns`** (closest to upstream); the opinionated detach-on-timeout policy lives in the my-pi `native-tool-aliases` extension, which calls the exported `onBashTimeout((t) => ({ backgroundedJobId: t.background().id }))` so Luke's `Bash` tool auto-backgrounds (Claude Code parity) while core stays neutral. Consumers override via `onBashTimeout(resolver)` (returns a restore fn) to detach, kill, log, or gate — without reshaping the upstream exec path (one call deep). Honours the additive-hooks principle: `core/tools/bash.ts` keeps its shape, the policy lives in the extension. Exported `onBashTimeout` + `BashTimeout`/`BashTimeoutOutcome` types from the package barrel. Seamed e2e coverage in `test/bash-timeout-background.test.ts`: default kill+timeout report, override-to-detach + bg read, and override-to-fail (seam sees real command/timeout, restore returns to default).

- **Fork-mode sub-agent prefix: switched from strip to placeholder-substitute (CC parity).** `getFilteredForkMessages` in `packages/coding-agent/src/core/agents/context.ts` used to drop parent `agent`/`subagent` `tool_use` blocks (and any associated `tool_result`s) from the fork child's message history. That broke prompt-cache continuity: the moment a stripped tool_use appeared in parent's actual cached prefix, every subsequent block in the child's request diverged byte-for-byte from the parent's cache key, busting cache reuse for the entire leading section. New behavior mirrors Claude Code 2.1.x `buildForkedMessages` (`src/tools/AgentTool/forkSubagent.ts`): keep parent's `tool_use` blocks in place, and for any unresolved `tool_use` (denied or simply incomplete at fork time) synthesize a fixed-bytes placeholder `tool_result` with text `"Sibling agent task in progress."`. New helper `substitutePlaceholdersForUnresolvedToolCalls` is exported alongside `getFilteredForkMessages`. The placeholder text is identical across every fork child spawned from the same parent state, so **sibling forks share cache with each other**, not just with the parent — the critical property for wide parallel fan-out via `tasks[]`. Cache parity contract: any two `getFilteredForkMessages(parentSession)` calls return byte-identical arrays through every leading block, with the per-child user directive (built by `buildChildTaskPrompt`) as the only divergence point. Removed the now-dead `filterDeniedToolArtifacts` helper; left a comment marker so future maintainers see the historical rationale. Regression tests in `packages/coding-agent/test/agent-context-inheritance.test.ts`: "fork filtering keeps parent agent/subagent tool_uses for cache parity", "fork filtering substitutes placeholders for unresolved tool_uses, drops orphan results", and "sibling forks produce byte-identical message arrays" (JSON.stringify equality on two consecutive `getFilteredForkMessages` calls). Side note: orphan `tool_result`s (results whose `tool_use` doesn't exist in the message stream) are still dropped — those would confuse the provider API and don't appear in parent's cached prefix anyway.

When a long-running server-side tool (`web_search` / `web_fetch` / `code_execution`) needs another turn to finish, Anthropic returns a partial assistant message and the client must echo it back unmodified to resume.
